# 代码覆盖率使用说明

平台只展示来自被测代码实际运行的覆盖率报告。HTTP 服务主页、接口响应和测试通过率都不能推算代码行覆盖率。没有真实报告时，“按配置采集”会返回原因，不会生成 0% 或 100% 的假报告。

## Go 项目（例如 IoTFast）

如果要统计**自动化接口测试请求触发的代码**，先由 CI 使用 Go 1.20+ 执行 `go build -cover`，部署独立的覆盖率测试实例，并在被测主机安装 [Coverage Agent](../test-agent/README.md) 和 Go 工具链。平台的「探针配置」选择 Go Agent，填写已登记的服务名、Agent URL 与令牌**环境变量名**。测试开始前 Agent 启动插桩二进制；测试结束后正常停止进程，把 `GOCOVERDIR` 转成 `coverage.out` 并关联本次 Test Run。进程启动和健康检查期间执行的语句也会计入本次进程级覆盖率。

原版 IoTFast 二进制由 Go 1.18 构建，不能直接从它的 HTTP 响应得到测试期间的代码覆盖率。生产环境应使用独立的覆盖率测试实例；仓库另提供 8203 的 Go 演示实例供验收。

本项目的虚拟机验收环境已将 IoTFast 8201 切换为 **Go 1.24 覆盖率构建 + Agent 按测试任务启动**。`iotfast.service` 已停用，以免占用 8201；Agent 常驻 8768。运行以下命令可重复执行一条真实 API 用例，并生成关联 Test Run 的覆盖率报告：

```bash
sudo docker exec -e PYTHONPATH=/app aitp-backend python /app/tests/manual_verify_coverage_agent.py --language iotfast
```

测试期间 8201 可访问，测试结束后 Agent 会停止该进程，故浏览器直接访问 8201 可能连接失败。要让平台项目使用该实例，选择 Go Agent：服务名 `iotfast-go`，Agent URL `http://host.docker.internal:8768`，令牌环境变量名 `COVERAGE_AGENT_IOTFAST_TOKEN`，工具 `go_cover`；虚拟机的后端和 Worker 已从 `.env` 注入令牌。此环境仅供验收，部署到其他主机时应为 Agent 使用 HTTPS 和独立的测试环境。

如果只需 **Go 单元测试**覆盖率，可在 Go 项目代码目录运行：

```bash
go test -coverprofile=coverage.out ./...
```

然后在平台“代码覆盖率”页面选择项目，点击“上传报告”，选择 `coverage.out`。页面显示的是 Go **语句覆盖率**；Go coverprofile 不含分支覆盖率，因此显示“未提供”。文件级明细可查看各源码行是否被执行。

如果只想运行部分包，也可以用 `go test -coverprofile=coverage.out ./library/libMath`。IoTFast 的 `http://192.168.125.128:8201` 返回前端 HTML，不能填作 HTTP 覆盖率报告地址。

## Python、Java 和其他 XML 报告

- Python：在被测项目执行覆盖率测试后运行 `coverage xml -o coverage.xml`，上传 XML。
- Java：使用 JaCoCo Maven/Gradle 报告任务生成 `jacoco.xml`，上传 XML。单独的 `.exec` 是探针位图，缺少类文件映射，不能直接作为行覆盖率报告。
- Node 等工具：生成 Cobertura XML 后上传。

“探针配置”中的 HTTP 策略只适用于**直接返回上述报告文本**的 URL。保存前可点击“校验报告来源”，它会检查内容格式。工作空间策略仅在关联测试任务且执行工作空间内已生成 `jacoco.xml`、`coverage.xml`、`coverage.out` 等报告时采集；运行中的普通服务 URL 不会自动产出报告。

旧版本按接口结果推算的报告在列表、看板和趋势中隐藏，原始数据库记录保留以便核对。
