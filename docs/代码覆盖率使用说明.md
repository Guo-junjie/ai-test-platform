# 代码覆盖率使用说明

平台只展示来自被测代码实际运行的覆盖率报告。HTTP 服务主页、接口响应和测试通过率都不能推算代码行覆盖率。没有真实报告时，“按配置采集”会返回原因，不会生成 0% 或 100% 的假报告。

## Go 项目（例如 IoTFast）

在 Go 项目代码目录运行：

```bash
go test -coverprofile=coverage.out ./...
```

然后在平台“代码覆盖率”页面选择项目，点击“上传报告”，选择 `coverage.out`。页面显示的是 Go **语句覆盖率**；Go coverprofile 不含分支覆盖率，因此显示“未提供”。文件级明细可查看各源码行是否被执行。

如果只想运行部分包，也可以用 `go test -coverprofile=coverage.out ./library/libMath`。IoTFast 的 `http://192.168.125.128:8201` 返回前端 HTML，不能填作 HTTP 覆盖率报告地址。

## Python、Java 和其他 XML 报告

- Python：在被测项目执行覆盖率测试后运行 `coverage xml -o coverage.xml`，上传 XML。
- Java：使用 JaCoCo Maven/Gradle 报告任务生成 `jacoco.xml`，上传 XML。单独的 `.exec` 是探针位图，缺少类文件映射，不能直接作为行覆盖率报告。
- Node 等工具：生成 Cobertura XML 后上传。

“探针配置”中的 HTTP 策略只适用于**直接返回上述报告文本**的 URL。保存前可点击“校验报告来源”，它会检查内容格式。工作空间策略仅在关联测试任务且执行工作空间内已生成 `jacoco.xml`、`coverage.xml`、`coverage.out` 等报告时采集；运行中的普通服务 URL 不会自动产出报告。

旧版本按接口结果推算的报告在列表、看板和趋势中隐藏，原始数据库记录保留以便核对。
