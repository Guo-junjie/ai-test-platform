# 第一批企业安全改造与部署说明

本批覆盖默认 API 认证、项目资源授权、权限测试和生产部署基线。组织/租户管理、SSO、限流与完整 Runner 隔离仍属于后续批次。

## 权限变化

- 除登录、健康检查和静态图表文件外，所有业务 API 默认要求有效用户 Token。未登录返回 401，角色或项目授权不足返回 403，隐蔽资源返回 404。
- 管理员可访问所有项目；其他用户只能访问本人负责或明确授权的项目。历史项目不自动向全部账号开放。
- 项目负责人或管理员在“项目工作区 → 项目成员”中按用户名授予只读/读写权限或撤销权限。成员修改写入审计日志。
- 全局角色是权限上限：viewer、auditor 即使获得项目读写成员资格，也不能修改业务资产、触发测试或创建分享链接；个人资料、通知和自己的知识会话仍可操作。
- 审计日志限管理员和审核员；模型配置、全局系统配置、代码解析和全局仓库配置限管理员。原始上传/代码测试入口限管理员，普通测试成员使用计划执行入口。
- 列表、统计、报告及结果等间接关联资源通过请求数据库会话统一过滤项目范围；新增与修改同时检查关联对象，防止跨项目写入。
- 知识文档、切片和检索按授权项目过滤。全局术语保留共享，未标注项目的历史非术语切片对普通用户关闭。

## 分享与集成

报告分享链接改为带签名凭证的链接，绑定报告、有效期七天。缺失、过期、串改或不匹配的凭证返回 401。旧的不带凭证的分享链接失效，需要在报告页重新获取。普通 GET 报告请求不再隐式触发模型生成。

GitHub Webhook 必须配置并验证 `GITHUB_WEBHOOK_SECRET`；未配置返回 503，不再跳过签名。通用 CI 触发和结果查询继续验证项目 CI Token。SVN 入口要求管理员登录 Token；质量徽章也需登录，不再匿名公开。

## 数据库升级

新增 Alembic `015`，只增加 `project_members` 表、主外键、权限值约束和用户索引，不删除历史业务数据。

已有版本为 `014` 时，在备份后先运行迁移，再部署应用。避免旧的热重载模式在迁移前执行 `create_all`。

```sh
docker compose exec -T postgres pg_dump -U aitp -d ai_test_platform -Fc > backup-before-security.dump
# 将新迁移文件放入可执行迁移的镜像/独立目录，使用相同数据库配置：
alembic upgrade 015
```

不应把未核实结构的数据库直接 `stamp head`。当前仓库仍有历史启动时补表逻辑，后续批次统一迁移体系；本批生产配置不是对历史迁移完整性的替代。

## 生产部署

`docker-compose.prod.yml` 为独立文件，不能与开发 Compose 叠加使用。生产拓扑使用独立命名卷，切换已有实例前必须迁移备份数据及对象存储，不能直接启动一个空实例冒充升级。

1. 将 `deploy/production.env.example` 复制为 `.env.production`。设置经过验收的镜像 tag，正式交付建议锁 digest；不使用 `latest`。
2. 为应用、PostgreSQL、Redis、RabbitMQ、MinIO 填写独立强凭证。**已有实例的 AES 密钥必须保留**；变更需要先迁移所有已加密配置，不能直接更换。
3. 后端镜像由更新后的 `backend/Dockerfile` 构建；前端使用 `frontend/Dockerfile.prod`，显式传入固定版本的 `NODE_IMAGE` 和 `NGINX_IMAGE`。
4. 后端/worker/beat 以 UID 10001 运行，前端以 UID 101 运行，应用根文件系统只读，临时目录和命名卷可写。迁移现有数据卷时，应先处理 `/app/data` 的 UID/GID。
5. 只有前端端口映射，默认绑定 `127.0.0.1:3000`；数据库、缓存、消息队列、对象存储和后端不映射宿主端口。外部访问由企业现有 HTTPS 网关反向代理；填写 `CORS_ORIGINS` 和 `REPORT_PUBLIC_BASE_URL`。
6. 配置包含应用健康检查、自动重启、CPU/内存/PID 限制、日志轮转、禁止提权和能力裁剪；关闭热重载、源码挂载和生产 Swagger/OpenAPI 页面。
7. 首次空库启动仅创建显式指定的管理员，`BOOTSTRAP_ADMIN_PASSWORD` 必须至少 16 字符。生产不会自动创建演示账号，也不会自动提升同名账号。已有实例的演示账号需管理员主动停用或改密。

```sh
# 只检查 Compose 结构，使用虚拟值，不读取真实凭证
python3 deploy/validate-production.py

# 配置真实部署变量后（--quiet 防止将解析后的密钥输出）
docker compose --env-file .env.production -f docker-compose.prod.yml config --quiet
docker compose --env-file .env.production -f docker-compose.prod.yml up -d
```

现有测试虚拟机采用保留原数据和账号的应用升级方式。生产拓扑是独立交付配置，不能视为已经完成当前虚拟机的生产切换、密钥轮换、TLS 接入和备份恢复演练。

## 验收

- `test_enterprise_access.py` 遍历全部已注册业务路由验证匿名访问，并验证角色矩阵、列表/聚合/别名/间接资源过滤、跨项目写入和分享凭证。
- `test_enterprise_http.py` 使用专用 PostgreSQL 数据库走真实 HTTP 请求，验证项目经理、管理员、viewer 和无成员资格测试员的行为。数据库名称必须以 `aitp_security_test_` 开头，并设置 `ENTERPRISE_ACCESS_INTEGRATION=true`，防止误用业务库。
- CI 增加 PostgreSQL 权限集成测试和前端类型检查/生产构建。
- 单元测试、前端构建、数据库迁移、部署后 API 冒烟均需通过后交付。

本批发布前验证结果：135 项后端测试通过（包含真实 PostgreSQL 集成）；前端 `vue-tsc && vite build` 通过；生产 Compose 渲染通过；以 UID 101、只读文件系统、禁止提权运行的 Nginx 配置检查通过。测试保留 3 条既有警告（Pydantic 字段命名与旧测试 AsyncMock），未新增测试失败。
