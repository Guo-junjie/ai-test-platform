# 缺陷中心 B/C 批次改造交付说明

## 交付范围

本批次完成缺陷协作、批量管理、导入导出、指标看板、项目级配置和自定义工作流。所有写操作继续沿用项目范围授权、角色校验、乐观锁、审计事件和软删除规则。

## 用户入口与操作流程

- 缺陷详情新增“评论与附件”：项目成员可评论、精确选择 @ 对象、关注缺陷、查看关注/抄送人，并上传、下载或删除附件。
- 缺陷列表新增多选与“批量处理”：先预览逐条权限及版本冲突，再执行指派、优先级、模块、迭代、标签、状态流转或删除。
- 页面右上角新增“指标与管理”：包含指标看板、保存视图、导入导出、项目配置和自定义工作流五个页签。
- 工作流发布后仅用于新缺陷；已有缺陷通过“迁移已有缺陷”先预检状态映射，再显式执行并逐条留痕。

## 数据结构

| 表/字段 | 用途 |
| --- | --- |
| `defect_comments` | 评论正文、@ 用户、编辑版本和软删除审计 |
| `defect_watchers` | 关注人与抄送人，项目内唯一约束 |
| `defect_attachments` | 私有对象键、文件摘要、MIME、大小和软删除信息 |
| `notification_outbox` | 与业务事件同事务写入的待投递消息 |
| `notification_deliveries` | 按用户和通道记录投递结果、次数与失败原因 |
| `defect_views` | 个人/项目共享筛选视图、列配置和排序配置 |
| `defect_jobs` | 导入预览、导入提交、导出和工作流迁移的幂等任务 |
| `defect_daily_metrics` | 按项目、时区和定义版本保存每日指标快照 |
| `notifications.*` | 增加来源事件、资源定位和幂等键 |
| `defect_workflows.active_revision_id` | 指向当前已发布版本 |
| `project_defect_settings.timezone` | 指标统计与日期边界时区 |

迁移顺序为 `019 -> 020 -> 021 -> 022`。020 新增 B/C 数据结构，021 兼容补齐时区字段，022 增加工作流当前版本和通知事件的引用完整性约束。

## 企业级约束

- 评论中的 @ 必须从当前项目有效成员中精确选择；正文文本不会被当作任意账号引用。
- 附件存入私有 MinIO 对象，下载必须重新鉴权；默认单文件 20 MB、单缺陷 200 MB，并校验扩展名、MIME、文件签名和文本编码。
- 通知采用事务 Outbox，站内信以事件、用户和通道组成幂等键；系统异常按退避策略重试，未配置的外部通道会保留明确失败原因。
- 当前可直接交付的通道是站内信。邮件、Webhook、钉钉等未配置传输器时会明确记录为失败，不会伪报成功。
- 批量操作最多 100 条并返回逐条成功/失败结果；导入最多 5000 行；导出最多 10000 条，并处理电子表格公式注入风险。
- 导入先预览后提交，任务请求号与内容摘要共同保证幂等；导出文件私有保存并设置过期时间。
- 自定义工作流只能组合平台支持的安全动作，不能注入脚本、扩大角色权限或削弱关键动作的必填规则；发布版本不可修改。
- 指标按工作流状态语义统计积压、解决、关闭和重开，支持项目时区，并返回历史数据完整性说明。
