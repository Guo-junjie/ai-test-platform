# 缺陷中心第一批改造交付说明

本批对应《缺陷中心企业级重构方案》的 A / P0 核心闭环。实现代码、默认流程、增量迁移和验证脚本已落地。B/C 能力不在本批交付范围，没有添加无后端支持的占位按钮。

## 1. 可以如何使用

进入「质量分析 → 缺陷中心」，选择项目。可从页首「登记缺陷」或空列表「登记第一个缺陷」打开抽屉；填写标题、描述、严重程度、优先级、类型、模块、迭代、环境、复现步骤、结果、人员、影响版本、标签、期限和需求/用例关联。

步骤可以增删、上下排序。支持保存及连续登记，提醒同名候选；同名不同问题可以明确确认后继续。关闭、刷新或跳转时保护未保存内容，保存后定位并高亮新增行。普通 HTTP / IP 地址访问也能生成请求编号。

负责人通过详情完成分诊与指派；开发提交修复版本或构建号，并确认修复已部署到可验证环境；测试人员填写实际验证版本或构建号与说明。状态为：新建 → 待分配 → 处理中 → 待验证 → 已解决 → 已关闭，另支持验证失败重开、关闭后重开、拒绝及退回待分配。当前身份可用的动作来自服务端。

默认禁止修复提交者验证自己的修复，即使后来将验证职责转派给该人也不能绕过限制。负责人代处理、代验证时必须说明原因。拒绝要说明结果，重复缺陷必须关联同项目主缺陷，关系不能成环。操作说明进入独立事件，不追加到复现步骤。

列表提供组合筛选、分诊队列、分配给我、我报告的、待我验证、逾期等内置视图。每行保留查看、流转、更多。详情支持独立链接、活动时间线、检测证据和需求/用例/缺陷关联；删除采用回收站，历史和检测证据保留。

## 2. 数据模型

保留原 `defects` 表、ID、旧五状态及 `is_resolved` 投影，新增业务编号、真实工作流状态、优先级、目录与环境快照、人员、复现与结果、版本/构建、来源、解决结果、标签、过程时间、重开次数、并发版本号及软删除字段。

| 新表 | 用途 |
| --- | --- |
| `project_modules` / `project_iterations` / `project_releases` | 项目模块、迭代和版本目录 |
| `defect_workflows` / `defect_workflow_revisions` | 默认流程及绑定的已发布不可变定义 |
| `project_defect_settings` / `project_defect_roles` | 项目配置基础结构及项目职责，配置编辑暂未开放 |
| `defect_affected_releases` | 一个缺陷的多个影响版本 |
| `defect_references` | 同项目需求、用例和缺陷关联 |
| `defect_events` | 顺序事件、操作者、字段前后值、说明及幂等请求结果 |
| `defect_occurrences` | 真实运行、执行用例、结果和检测签名 |

所有写操作在同一事务中完成字段更新、事件和审计日志。更新请求要求 `expected_version`；分配/流转要求 `request_id`，创建要求 `creation_request_id`。相同请求重试不会重复写入；请求号复用不同内容返回 409。数据库行锁与版本号共同阻止覆盖他人的修改。

停用目录和账号不抹掉已关联的历史。仅修改描述时不重新绑定原环境快照，也不强制改掉停用模块或影响版本。有业务历史引用的用户删除改为停用，保留责任人与审计身份。

## 3. 接口

响应继续使用 `{code, data, message}`；详情额外返回 `permissions`、`transitions` 和业务名称。新接口均需要登录并执行项目隔离和职责校验。

| 方法及路径 | 功能 |
| --- | --- |
| `GET /api/defects` | 组合筛选、分页、内置视图、当前筛选统计及项目回收站 |
| `GET /api/defects/metadata` | 状态、选项、项目目录、环境、需求、用例及可用职责 |
| `GET /api/defects/participants` | 当前项目启用人员，可按处理/验证用途查询 |
| `GET /api/defects/duplicates` | 同项目同名候选，不按标题自动合并 |
| `POST /api/defects` | 幂等登记，只允许手工来源 |
| `GET /api/defects/{id}` | 实时详情、关联对象、服务端权限和动作 |
| `PUT / PATCH /api/defects/{id}` | 有版本校验的编辑 |
| `POST /api/defects/{id}/assign` | 指派或转派处理/验证人员 |
| `GET / POST /api/defects/{id}/transitions` | 可用动作 / 执行动作 |
| `GET /api/defects/{id}/events` | 按事件序号翻页；保留原值并提供业务名称展示值 |
| `GET /api/defects/{id}/occurrences` | 自动发现的真实检测证据 |
| `POST / DELETE /api/defects/{id}/references[/{reference_id}]` | 添加或移除同项目关联 |
| `DELETE /api/defects/{id}`、`POST /api/defects/{id}/restore` | 带版本校验的软删除 / 恢复 |
| `GET / POST /api/projects/{project_id}/{modules,iterations,releases}` | 项目目录读取 / 创建 |
| `PATCH /api/projects/{project_id}/{modules,iterations,releases}/{id}` | 项目目录更新或停用 |

旧 `PATCH /api/defects/{id}/status` URL 仍存在，但必须提供版本、请求号和合法动作需要的资料；它使用同一领域服务，不能任意跳状态。需要直接跳转旧状态的外部调用方必须更新请求契约。

```json
{
  "action_id": "submit_fix",
  "expected_version": 4,
  "request_id": "3bb3c5d4-f70a-4f19-80d1-ae11be364839",
  "note": "调整优惠计算并部署到测试环境",
  "fields": {
    "fix_build": "orders-20261009.3",
    "verifier_id": "90b8a6d0-c586-486b-9977-e34b99ae925a",
    "fix_available": true
  }
}
```

## 4. 自动发现与统计口径

报告落库不再删除重建缺陷。以真实运行及执行用例建立稳定检测签名，不使用 AI 标题作为身份。重复生成报告保留 ID、人工编辑、处理状态和事件；旧 AI 分组改变主用例时仍为每一条真实失败保留检测记录。

无法关联本次真实失败结果的 AI 建议仍留在报告，不伪造成缺陷资产。环境不可达等基础设施故障不进入产品缺陷闭环。跨运行故障不自动合并或自动重开旧缺陷。

仪表盘和质量趋势按缺陷自己的创建时间、归属项目统计，包含不挂测试运行的手工缺陷；普通统计排除软删除记录。当前积压排除已解决、已关闭和拒绝。历史报告仍保留当时检测内容。

本批没有新增修复时效及事件趋势看板，原趋势仍表达创建数量，不冒充每日关闭或修复数量。

## 6. 迁移与验证

先备份并执行只读预检，再停止后端与任务消费者，更新代码、执行 `alembic upgrade head`，确认 019 后再启动。已有库不能仅依赖 `create_all` 补列。019 冻结 DDL 与默认工作流，后续代码修改不会改变已发布迁移的定义。

```bash
docker compose exec backend python scripts/verify_defect_migration.py
docker compose run --rm --no-deps backend alembic upgrade head
```

未知旧状态阻止迁移，事务回滚且保持 018。正常迁移保留旧步骤和创建时间，通过运行回填项目，缺少的报告人、处理人和过程时间仍保持未知。已验证/已关闭的历史结果标为 `legacy_unknown`，不补造可信验证；历史已解决记录需要重开补验后才能再次关闭。无法归属项目的记录保留且仅管理员可见，补归属操作留待后续管理能力。

019 不提供会删除协作历史的自动 downgrade。回退需采用兼容代码，或停止写入后恢复完整备份，不能重新启用删除重建缺陷的旧报告代码。

已在复制业务库的隔离 PostgreSQL 验证：213 项后端回归通过，1 项原有企业 HTTP 测试因专用环境条件跳过。本批自己的真实 HTTP / PostgreSQL 验收已实际执行，包含测试经理、测试人员、开发、只读成员及跨项目身份。两个独立连接同时编辑验证了行锁等待与 409 冲突。另用 7 种旧状态夹具验证 018→019 迁移与异常状态阻断回滚。

在隔离夹具库实际执行数据库清理，确认全部新增业务表清空、AI 模型/路由和初始化账号及密码哈希保持不变，之后还能初始化默认流程并登记缺陷。此清理验收没有作用于线上数据。

浏览器 10 组验收通过：登记与校验、步骤排序和连续保存、同名/未保存提醒、分诊指派、修复必填、版本冲突保留输入、验证关闭重开、活动与证据、编辑冲突展示最新修改并明确确认、内置筛选/错误重试及移动端布局；无页面脚本异常。前端 `vue-tsc + vite build` 通过。
