# IOTFast 物联网安全管理平台 - 测试策略与用例设计指南

## 文档基本信息
- **文档编号**：`IOTFAST-TEST-GUIDE-V1.0`
- **指导原则**：基于 ISO/IEC/IEEE 29119 标准及企业分层自动化测试金字塔模型
- **适用场景**：功能回归测试、API 接口自动化测试、MQTT 协议契约测试、安全合规渗透测试

---

## 1. 测试策略与分层质量模型

平台测试采用**分层测试策略**，确保从底层数据校验到上层端到端业务流的全方位质量保障：

```
       /\
      /  \      [E2E 系统端到端测试] (用户业务闭环、设备全生命周期流转)
     /    \
    /------\    [物联网协议专项测试] (MQTT 弱网模拟、QoS 保活、高频丢包校验)
   /        \
  /----------\  [接口契约与自动化测试] (RESTful API、边界值、异常参数、鉴权校验)
 /------------\ [底层单元与数据一致性测试] (加密算法、数据转换、ORM 事务回滚)
```

## 2. 接口自动化测试规范与断言标准

### 2.1 基础公共校验断言规则
1. **HTTP 状态码契约**：除 404/500 等协议层异常外，应用层请求 HTTP 响应码必须恒为 `200`；
2. **业务状态码约定**：
   - 业务成功：`code == 0`，且 `message` 应具备友好提示；
   - 业务失败：`code != 0`，`data` 不应泄露系统底层堆栈（如 SQL 错误敏感信息）；
3. **响应耗时门限**：
   - 单接口并发压测下，响应时延应满足：平均耗时 < 100ms，P95 < 200ms。

### 2.2 接口参数边界值测试设计要点
- **分页参数 (pageNum, pageSize)**：
  - 边界值：`pageNum = 0`, `pageNum = -1`, `pageSize = 0`, `pageSize = 10000`；
  - 预期行为：系统应自适应保底（`pageNum` 兜底为 1，`pageSize` 截断为合理上限如 100），不得抛出 500 异常；
- **字符长度与特殊字符测试**：
  - 用户名/设备编码输入特殊字符：`' OR '1'='1'`, `<script>alert(1)</script>`, `SELECT * FROM`, 超长 500 字符；
  - 预期行为：系统进行强类型校验或参数转义，拦截非法输入。

## 3. 物联网协议与 MQTT 专项测试标准

### 3.1 MQTT QoS 级别测试用例
- **QoS 0 (At most once)**：发送遥测数据，验证无须服务端 ACK 回执，消息正常流转入库；
- **QoS 1 (At least once)**：模拟弱网偶发丢包，客户端必须重发 PUB 消息，Broker 成功返回 PUBACK；测试幂等性是否避免数据脏写；
- **QoS 2 (Exactly once)**：完成完整的四次握手（PUBLISH -> PUBREC -> PUBREL -> PUBCOMP），确保关键控制指令只被投递且执行一次。

### 3.2 设备连接生命周期与保活测试
- **KeepAlive 心跳机制验证**：设置心跳间隔为 60 秒，验证设备在 1.5 倍心跳（90秒）未发送 PINGREQ 时，服务端主动将设备标记为 Offline；
- **网络震荡与断线重连**：模拟设备物理断网 10 秒后恢复，验证设备自动重连成功并补传未确认数据包；
- **遗嘱消息 (Will Message) 验证**：配置设备异常掉线触发遗嘱消息，验证监听主题能准确捕获设备异常掉线事件。

## 5. 缺陷等级评定与质量验收标准

### 5.1 缺陷严重度等级 (Severity Matrix)
- **P0 致命 (Blocker)**：系统崩溃、服务进程宕机退出、数据全量丢失、核心鉴权完全失效（任意用户越权免密登录）；
- **P1 严重 (Critical)**：主干业务链路阻断（如设备无法上线、登录鉴权全部失败、遥测数据无法落库入表）；
- **P2 一般 (Major)**：次要功能异常（如查询列表分页计算错误、排序字段失效、批量导出偶发失败）；
- **P3 轻微 (Trivial)**：UI 布局对齐瑕疵、提示语错别字、非关键字段缺失。

### 5.2 准出与发布质量门禁 (Quality Gate)
1. **自动化用例通过率**：P0 / P1 核心用例通过率必须达到 **100%**；
2. **总用例通过率**：全量测试用例通过率必须 >= **98%**；
3. **遗留缺陷控制**：发布版本中 P0/P1 缺陷必须清零，P2 缺陷遗留不得超过 2 个且必须有规避方案。
